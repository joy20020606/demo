# 領域小抄 — 博錸生技 / 多重檢測儀器

> 給非生技背景的工程師。面試前翻這頁就夠。

## 一句話總結
博錸做的是**癌症基因檢測儀器 + 試劑**。核心賣點是「一份檢體同時測幾十個基因位點」(multiplex,多重檢測),而不是一次測一個。

---

## 名詞

| 名詞 | 白話 | 對 UI 的意義 |
|---|---|---|
| **biomarker(生物標記)** | 一個「要檢查的項目」,像健檢報告的血糖、膽固醇。癌症檢測的項目是 EGFR L858R、KRAS G12C 這類基因變異點 | 明細面板的每一列 |
| **96 孔盤(96-well plate)** | 一塊塑膠板挖 96 個米粒大凹槽,8 列 × 12 行。生技界的 A4 紙 | Plate Map 的 8×12 格子圖 |
| **孔(well)** | 一個凹槽,裝一個病人的檢體 | 一個可點選的格子 |
| **multiplex(多重檢測)** | 一個孔同時測很多個 biomarker | **一孔 → 一份報告**,不是一孔一個數字 |
| **πCode® MicroDisc** | 博錸專利:孔裡漂著幾十顆刻有影像編碼的微盤,每顆負責一個 biomarker。機器拍照解碼後分別讀值 | 這就是「一孔多值」的來源 |
| **incubator(恆溫箱)** | 加熱到 37°C 讓反應發生 | Protocol 步驟之一 |
| **washer(清洗器)** | 沖掉沒結合上的雜質 | Protocol 步驟之一 |
| **protocol** | 機器要跑的步驟腳本(孵育幾分鐘 → 清洗幾次 → ...) | Dashboard 的步驟時間軸 |
| **sample-to-answer** | 上樣後不用人工介入,直接出結果 | UI 要能長時間無人看管 + 一眼看進度 |
| **IVD / CE IVD** | 體外診斷用醫材 / 歐盟認證 | 醫療級 UI:誤操作成本高 → 危險操作要二次確認 |

---

## 機器實際跑一輪

```
加樣 → 37°C 孵育 30min → 清洗 ×3 → 加試劑 → 孵育 20min → 清洗 ×3 → 拍照讀取 → 完成
                                                              總計 1~2 小時
```

操作員會走開,回來要一眼知道「跑到哪、剩多久」→ UI 需要 stepper / timeline(就是網購的「已出貨 → 配送中」那條線)。

---

## 為什麼「一孔多值」改變了 UI 設計

用後端的講法:資料結構從**扁平表**變成**一對多**。

| | 資料結構 | UI |
|---|---|---|
| 一般儀器 | `Well { double Value }` | DataGrid / 熱區圖就完事 |
| 博錸 | `Well { Marker[] Markers }`(24~100 筆) | **master-detail** 三層架構 |

就跟 `Order → OrderItems` 一樣:你不會把 OrderItems 硬塞進列表,你會做「左選右看明細」。

### 三層資訊架構
```
1. 盤    96 格總覽      一眼看出哪些檢體異常
2. 孔    點選一個病人
3. 指標  右側面板,24 條 biomarker 橫條圖
```

### 四個 UI 難點(demo 要秀的)
1. **壓縮** — 96 格畫得下,但每格有 24 個值。要決定「怎麼把 24 值壓成一個顏色」(最大值?異常項數?)→ 這是 UX 決策
2. **觸控** — 格子小、戴手套手指粗 → pinch zoom 必要
3. **明細排版** — 24 條要在有限空間看得懂 → 橫條圖不是表格
4. **效能** — 96 格不能做成 96 個 UserControl → 單一 Canvas 手繪

---

## 面試可用的一句話

> 「看官網之後我發現這不是一般『一孔一個讀值』的儀器 —— πCode 是一孔展開成一份多重報告。所以我把 Plate Map 設計成盤→孔→指標三層,而不是單純的熱區圖。難的地方在於 96 格總覽時要把每孔幾十個值壓縮成一個視覺訊號,這是 UX 決策不是技術決策,實際上應該跟臨床端一起定。」
