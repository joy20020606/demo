# 0001:案場差異放在設定檔,不放在程式

日期:2026-10-14
狀態:採用

## 背景

每個案場的設備品牌、暫存器位址、倍率、資料寬度都不同。案場 A 的耗電是一格暫存器、單位 0.1 kW;案場 B 是兩格合成一個數、單位 W。

需求 R1 要求新增案場時不修改程式。

## 決定

- 每個案場一份點位表(`sites/<site_id>.yaml`),描述每個點位的位址、倍率、單位與資料型別。
- 程式只有一套。全系統只認點位的 `name`,不認位址。
- 只有「通訊協定不同」才新增類別:實作 `PointReader` 並登記到 `READERS`。「案場不同」只新增設定檔。
- 點位表在啟動時以 Pydantic 驗證。欄位打錯、缺少必填欄位、位址重疊、名稱重複,都會讓 gateway 啟動失敗並指出位置。
- Gateway 的 image 不包含點位表,執行時才掛載。所有案場使用同一個 image。

## 考慮過但不採用的做法

| 做法 | 不採用的原因 |
|---|---|
| 每個案場一個子類別 | 案場數量等於類別數量,每次上線都要改程式與重新部署 |
| 程式內以 `if site_id == ...` 處理特例 | 特例會持續累積,且無法由非後端人員維護 |
| 點位表存資料庫 | 案場數少時,放在 git 可以直接得到修改紀錄與審查流程;需要讓非工程師在畫面上編輯時再搬 |

## 後果

- 新增案場:寫一份 YAML,啟動一個 gateway 容器。
- 新增協定(例如 BACnet):新增一個 reader 類別,其餘程式不動。
- 驗證只能抓到「格式錯誤」。倍率填成合法但錯誤的數字(0.1 寫成 1)不會被擋下,讀到的值會是 10 倍。這由需求 R2 的範圍檢查處理。
- 遇到設定檔無法表達的設備(例如需要位元運算的狀態碼)時,會在點位表加入具名的轉換方式,而不是為該案場寫分支。目前沒有這種點位,所以尚未實作。
